## 实施顺序与验收

1. **环境和来源检查**：确认本机 Linux、ROS、Slicer、资源、可用端口和已有进程；选支持 UR12e 的官方固定版本，记录来源和摘要。网络/安装失败保留日志，解决原因后再继续。
2. **URSim 部署**：安装所需容器运行时，使用本机专用网络和有明确身份的容器；配置 External Control 1.0.5，持久保存程序。验收虚拟控制柜实际版本、型号、运行状态和界面。
3. **ROS 基础控制**：增加独立的 URSim launch 与生命周期入口，保留 mock 默认行为；核对控制器、实时状态和执行程序。验收状态读取、简单点位运动、反馈和停止，保存原始日志与失败记录。
4. **Slicer 联动**：复用现有文件桥，明确区分 mock / URSim 来源；用面板目标完成规划和执行，保存截图、请求与反馈。界面动画不能替代控制器执行证据。
5. **交付与回归**：运行相关离线和实际运行检查；更新 README、部署说明、子目录说明与发布白名单。提供安装/启停/运行入口、量化结果、已知问题及现场接入尚缺项。

## 本次运行边界

- 仅本机 UR12e 仿真，ROS_DOMAIN_ID=62、ROS_LOCALHOST_ONLY=1；不连接实验室网络或真实设备。
- URSim 网络端点由本任务专用容器确定，不向任意 robot_ip 开放运动入口。
- 普通用户构建、启动和实验；root 只用于安装依赖。只停止核实属于本任务的进程和容器。
- 无物理定位精度、工具实物标定、影像导航实测或 ASTM 合规结论。现有简化工具仍是 tool0 +Z 120 mm。
- 当前机器为 Windows 宿主 + WSL2 / WSLg；本次通过不等于原生物理 Linux 或真机控制性能通过。
